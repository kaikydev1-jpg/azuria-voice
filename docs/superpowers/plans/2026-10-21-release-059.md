# Windows 0.5.9 release plan

Goal: deliver the merged PR #9 fixes through the next Windows installer and
verify the existing user's data, model licences, and installed voice still work.
The owner requested continuation of the described release/install steps.

- [ ] Bump root package.json, pyproject.toml, backend version fallback and lock
  to 0.5.9; promote Unreleased notes and update the distribution guide.
- [ ] Run the active Windows validation on pull requests as well as main,
  under the required Tests (backend + frontend) job name. Include the real
  backend suite and security regressions with an empty HF cache/offline mode.
  Preserve existing Electron checks, installer build, and setup smoke test.
- [ ] Validate the small release diff locally, obtain an independent review,
  create a release PR and read remote review results. Merge only with the
  exact-head Security and Tests checks green and MERGEABLE.
- [ ] Wait for main's own checks and download its exact-version installer.
  Verify SHA-256 assets and updater SHA-512 before installing.
- [ ] Snapshot user settings, voice/project files and licence records; install
  and update the existing managed Python runtime through the app's setup flow.
  Reuse cached Kitten weights for an offline voice smoke; no new consent.
- [ ] Publish the validated installer, blockmap, feed and checksums from the
  exact main commit, with user-facing changelog notes. Verify public download
  digests and updater feed; keep a local delivery copy and evidence.

Constraints: Windows x64 only in this release. Do not claim that the remaining
dependency advisories are fixed. Preserve all compute paths and model engines.
Do not change persistent storage names, erase models or accept new model terms.
Rollback: retain the immutable 0.5.8 assets and the pre-install data snapshot;
do not overwrite a published tag or point the updater at untested bytes.
