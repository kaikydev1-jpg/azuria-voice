vulnerabilidades”.

## Validação

- Guarda Stanza: testes com um payload inofensivo que só registra a execução
  numa lista. Sem a guarda, o fallback do Stanza 1.10.1 executa o payload
  (controle); com a guarda, a carga é recusada e nada executa. Checkpoints
  apenas com pesos continuam carregando; outros chamadores mantêm o modo.
- A etapa Linux anterior não executou tradução ou transcrição reais. A
  validação Windows posterior executou tradução Argos com um pacote baixado
  após autorização expressa do proprietário, em diretório isolado. Nenhum
  modelo pessoal ou dado do aplicativo instalado foi usado. Transcrição
  real e GPU continuam fora desta validação.

## Limites e próximo passo

- O bloqueio de `download.pytorch.org` impediu a regeneração na etapa Linux
  anterior. A etapa Windows abaixo alcançou o índice e concluiu o lock e os
  testes. O override ainda contraria o pin declarado pelo Argos: sua
  compatibilidade é sustentada pelos testes descritos, não por uma nova
  declaração de suporte do mantenedor Argos. Mac/Linux com essa combinação
  e outros pacotes de idioma ainda precisam de ensaio real.
- Setuptools e Torch dependem de uma versão do WhisperX compatível com
  `huggingface-hub>=1` e Torch ≥2.13. Retestar a cada versão do WhisperX.


## Validação Windows do Stanza corrigido — 21/10/2026

Ambiente isolado em `C:\AzuriaVoiceTest`, Windows x64, Python 3.11.17,
Argos Translate 1.11.0, Torch 2.8.0+cpu e CTranslate2 4.4.0. A instalação
Azúria Voice 0.5.9, seus modelos, vozes, dados e registros de licença não
foram alterados. Não houve merge, mudança de versão ou publicação nesta etapa.

| Verificação | Resultado |
|---|---|
| Sincronização antes/depois | `uv sync --frozen --python 3.11 --no-default-groups --group cpu --group dev` passou nas duas versões. |
| Backend, regressões do workflow Windows e sete suítes de tradução do repasse | **742 passaram, 9 ignorados** com Stanza 1.10.1; **742 passaram, 9 ignorados** com Stanza 1.12.2. Cada execução usa dados temporários próprios e Hugging Face offline com cache vazio. |
| Piso de segurança Stanza | O teste existente de pisos falhou com `stanza: 1.10.1` após incluir o mínimo 1.12.2; passou com o novo lock. |
| Lock | Gerado pelo uv, conferido com `uv lock --check`; muda Stanza 1.10.1 → 1.12.2 e acrescenta somente sua cadeia `udtools` → `udapi`. As demais entradas existentes permanecem idênticas. |
| Tradução real antes/depois, CPU | `Hello world. This is a short test.` → **`Olá, mundo. Este é um teste curto.`**, sem mudança na saída, com a guarda habilitada e tokenizer Stanza real nas duas versões. |

O pacote de teste é o [en→pt 1.9 do índice oficial Argos](https://raw.githubusercontent.com/argosopentech/argospm-index/main/index.json),
obtido de [argos-net.com](https://argos-net.com/v1/translate-en_pt-1_9.argosmodel):
66.179.184 bytes, SHA-256
`0c5350a2fa5b923de1346edc0d42e08e38bab2e33cede3a0b9a48eb4281ad8a9`.
O README atribui o modelo derivado OPUS-MT a Jörg Tiedemann e Santhosh
Thottingal e informa CC-BY 4.0; esse aviso foi preservado na cópia de teste.
O hash é o medido no download, não uma assinatura fornecida pelo mantenedor.
O pacote não integra o instalador ou este repositório.

Uma tentativa intermediária reutilizou o banco temporário da primeira
execução e falhou em dois testes (perfil duplicado e eventos acumulados).
A causa foi o script externo de validação: `conftest.py` respeita um
`OMNIVOICE_DATA_DIR` já definido. O script passou a criar um diretório de
dados novo por execução; a suíte completa repetida passou sem alterar os
testes ou o produto para esconder essas falhas. Essa tentativa foi mantida
nos registros locais.
